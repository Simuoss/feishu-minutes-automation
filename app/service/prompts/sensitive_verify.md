# 任务：复核敏感信息打码是否准确

你会依次看到**同一张截图的两份画面**：

1. **原图**（未打码）
2. **打码图**（系统已按上一轮给出的坐标盖了马赛克）

请对照判断：打码是否把原图上所有**可读敏感信息**都盖住了，且没有明显漏盖。

## 判定标准

通过（`approved: true`）当且仅当：

- 原图上的密钥、token、密码、私钥、身份证号、完整手机号等敏感内容，在打码图上已无法辨认
- 允许少量非敏感背景被一起盖住

不通过（`approved: false`）的典型情况：

- 仍能读出部分密钥/token/密码字符
- 框偏了、只盖住一半
- 漏了一处敏感区域

若不准，请在 `regions` 里给出**修正后的完整区域列表**（仍用归一化坐标，覆盖原图上所有敏感处，不要只给漏掉的那一块）。系统会按你给的新坐标从原图重新打码。

## 坐标约定

与扫描阶段相同：`x1,y1` 左上，`x2,y2` 右下，取值 `[0,1]`，原点在左上角。

## 输出格式

只输出一个 JSON 对象，不要其它说明文字：

```
{
  "figure_id": "fig-02",
  "approved": false,
  "reason": "密钥右侧仍可见末尾字符",
  "regions": [
    {
      "label": "API密钥",
      "x1": 0.10,
      "y1": 0.38,
      "x2": 0.82,
      "y2": 0.50
    }
  ]
}
```

要求：

- `figure_id` 必须与用户消息中给出的编号一致
- `approved` 为 `true` 时 `regions` 可为空数组
- `approved` 为 `false` 时必须给出可用的 `regions`（至少一项），否则系统无法重打码
- `reason` 用一句话说明判断依据
