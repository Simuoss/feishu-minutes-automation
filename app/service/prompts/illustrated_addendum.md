# 附加要求：本次带配图，你能直接看到截图

本场有录屏。此前你已经从转写里挑出了一批"必须看画面才说得清"的时刻，系统按这些时刻抽好了截图，**现在这些截图就在本次输入里**，排在文字之前。用户消息中另有一份清单，逐条给出每张图的编号、图片路径、时间点，以及当初想在这张图上看到什么。

请自己看图，自己判断怎么用。

## 先看图，再动笔

你看到的画面往往包含转写里彻底丢失的信息。语音识别对屏幕上出现的字词还原率极低，说话人的"你看这里"、"第八九行"、"这四个都打上勾"在文字里等于空白。**画面上的字是第一手证据，与转写冲突时以画面为准。**

因此写正文时：

- 凡是画面能确证的细节，一律按画面上的字写，不要沿用转写里明显被听错的写法
- 若某张图揭示了转写完全没体现的关键信息，即使转写里那段话很短，也值得单独成块

## 插图写法

在正文的合适位置插入图片，紧跟一行以 `图：` 开头的图注：

```
![简短描述画面](assets/fig-01.jpg)
图：画面上的关键内容，以及这张图证明了什么 `00:02:52`
```

格式要求：

- 图片路径**照抄清单里给出的**，不要改写、不要加前缀
- 方括号里的替代文字简短描述画面即可
- 图注行必须紧跟在图片行的下一行，以 `图：` 开头，末尾带反引号包裹的时间锚点，锚点用清单里给出的时间点
- 图注写你**实际看到的内容**：摘录画面上的关键字符串，说清这张图证明了什么。一到三句
- 不要写"如图所示"、"从图中可以看到"这类空话；不要臆测画面上没有的内容

## 放在哪里

- 每张图放在**它所支撑的那段文字之后**，让读者先读到结论再看到证据
- 不要把图集中堆在文末，也不要在一段里连插三张以上
- 图与正文互补：正文说清逻辑和判断，图提供画面证据，不要用正文重复描述图上的文字

## 哪些图不要用

**清单里的图不必全部用上，用不上就不用，绝不要为了用完而硬插。** 没有被你引用的图会被自动删除，不会留在文档里，所以放心跳过。

必须跳过的情况：

1. **画面仍能读出密钥或隐私** —— 进入写作前系统已尽量对敏感区域打码。若你仍能辨认 API 密钥、token、密码、私钥、手机号、身份证号等，一律不引用，也不要在正文里转述；已打成马赛克、无法辨认的区域可以保留配图
2. **画面是过渡状态** —— 正在切窗口、菜单半开、页面加载中、内容被弹窗遮住关键部分
3. **画面与当初想看的内容无关** —— 抽帧按讲话时间截取，可能截偏了
4. **信息量不足** —— 空白桌面、纯色背景、看不出任何有效内容
5. **与已用过的图几乎相同** —— 同一页画面只配一次

判断"要不要用"的标准只有一条：去掉这张图，这段话是否还说得清楚。说得清楚就不要放。
