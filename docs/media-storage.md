# 媒体存储与 R2

开桶、填 `.env`、CORS 这些操作步骤在 [根目录 README](../README.md#b-cloudflare-r2媒体)，这里讲哪些东西上云、为什么。

## R2 上放什么

| 时机 | 行为 |
|------|------|
| 配图生成并脱敏后 | 上传 R2，DB 登记；可删本地配图 |
| 下载完成后 | 有视频才压成分享片 → 上传 `…/share/video.mp4` |
| 自建转写 / 声纹提炼 | 音轨传 `…/audio/asr.mp3` 并长期保留，原片可删后仍能复用 |
| 本地导入大文件 | 浏览器直传 `…/import/{filename}`，服务器拉回后删掉该对象 |
| 纪要完成且分享片 READY | 清理本地原片（避免磁盘堆积） |
| 播放 / 分享读图 | 优先 R2 签名 URL；未就绪回落本地 |

压缩默认：高度 ≤720、`libx264` + `veryfast` + CRF 32、AAC 64k、`+faststart`。R2 对象 key 与同步状态在库表 `r2_sync_states`。

桶保持私有，一律用短时签名 URL，没有公开读。浏览器要直接读图、播分享片、直传导入文件，所以桶得放开 CORS（[怎么配](../README.md#3-桶-cors浏览器要直接连-r2)）。

## 转写与纪要不进 R2

这两份文本一直只存本地，读的时候直接读盘，跟着接口一起发给前端。它们只有几十 KB，走直链省下的传输还不够多一次握手的开销；而且说话人的真名是读取时才贴上去的，直链会绕过这一步。

## 音轨从哪来

原片在纪要完成且分享片上云后就被删了，但 [自建转写](transcription-and-voiceprint.md) 和 [声纹提炼](voiceprint-harvest.md) 都还要吃音轨，所以取音轨按代价从低到高回落：

1. 本地现成的音轨
2. R2 上现成的（跑过一次自建转写的会议，音轨是长期保留的）
3. 本地媒体现抽一份
4. 回飞书重下原片、抽完音轨再把原片删掉

[本地导入](local-import.md) 的会议没有最后这条路，飞书上不存在对应妙记。

## 没开 R2 会怎样

R2 是可选的。关掉之后：配图与视频都从本机读，分享页播放走本机（公网的话就是走 Tunnel 回源，大文件会慢）；本地导入一律走服务器上传；自建转写与声纹提炼不可用，因为识别服务需要一个能公网访问的音频直链。
