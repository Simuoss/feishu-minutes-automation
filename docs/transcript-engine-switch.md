# 手动切换转写引擎

自动流程只在飞书那份被截断时才转自建，但有时人工判断更准：飞书转写虽然覆盖全程却错字连篇，或者反过来自建识别把专有名词念歪了。详情页转写区因此有一行来源标识和两个切换按钮：

```
POST /api/v1/meetings/{minute_token}/transcript/source
{"source": "asr" | "feishu"}
```

**切到自建转写**：校验 R2 与 `STEP_ASR_ENABLED` 都开着、这场会议拿得到音频，然后把 `transcript_source` 置空并排一条 `TRANSCRIBE`。置空而不是直接写 `asr`，是因为转写真跑成了才算，失败时覆盖率判定还能重来。跑完之后写来源、刷参会人、强制重跑纪要这一串沿用既有逻辑。ASR 是按量计费的，所以前端会弹确认框。

**切回飞书转写**：删掉 `transcript.asr.txt`（只要它还在，所有读路径都优先读它），本地没有飞书原文就重下一份，然后清掉这场会议的说话人映射与样本——自建那套「说话人N」编号已经作废，留着只会让展示层贴错名字——最后强制重跑纪要。[本地导入](local-import.md) 的会议会直接拒绝，飞书上没有对应妙记可切回。

两个方向都会先看有没有转写作业在排队或进行中。入队对同类型进行中作业是静默去重的，手动操作必须把「已经有一个在跑」说出来，而不是假装成功。
